# 我们现在在哪里

*Earthlings 人民。二〇二六年九月十九日的状态*

## 这份文件是做什么的

我们说，Earthlings 是可验证的。这样的说法只有在能够确切指出验证的对象和验证的方式时，才有意义。因此，我们不用“我们的代码是开源的”这类笼统说法，而是公布一条准确的界线：什么是开放的，什么是封闭的，出于什么原因。

自二〇二六年十月二十二日起至《宣言》通过之日止，为创立期：人民仍在创立之中，下面列出的一部分数字，在这一时期的读法与通过之后不同。它的规则载于 [创立期](https://earth-lings.org/documents/zh/zh20-the-founding-period.html) 这份文件——这里不再重复。

> **原则。** 开放的是人民的可验证性所依赖的东西：护照的规则、记录的名册、公开的投票渠道和共同资金；今天还得相信我们的地方，写在下面。封闭的是那些公布之后并不增加可验证性、却会给参与者带来风险的东西：服务器端的支撑部分和个人数据的处理。

## 什么是封闭的，为什么

| 组成部分 | 原因 |
|---|---|
| 平台的服务器端 | 其中包含访问账户的逻辑。在独立审计之前公布它，会提高参与者账户被攻破的风险，同时对人民的可验证性毫无增益。 |
| 身份验证系统 | 它处理证件和生物特征。这里的封闭是个人数据保护的一部分，而不是隐瞒。身份验证中数据最小化如何实现，《生物特征验证政策》和《隐私政策》中有说明。 |
| 部署用的基础设施 | 其中包含服务器的配置。公布它等于给攻击者一张地图。 |

谁得到名册中的记录、谁参加投票，开放的智能合约并不决定：向谁发放记录，由封闭的身份验证系统决定，而投票时的投票权由我们的服务器确认。合约只记录发放和销毁，而其中的每一次都可以不通过我们在网络中看到；究竟在哪些地方还得相信我们，见下文。

## 现在就可以查验，而不必信任我们的东西

- **Earthlings 护照的规则。** 在仓库里读合约的源代码：护照不可转让，一个钱包一本，持有人可以自己销毁。
- **名册里有多少条记录。** 通过 Polygon 网络的任何一个节点调用合约的 `totalSupply`：该合约在浏览器中未经验证，因此那里没有读取的页签。这个数字不是我们说出来的——是区块链说出来的。但这个数字需要读对，怎么读我们会说明。**目前那里有四条测试记录**，是系统启动之前调试时留下的，其中没有真实的参与者；它们仍然计入这个数字。**自二〇二六年十月二十二日起至文本通过之日止**，这个数字减去四条测试记录，表示已通过身份验证、正在参与创立的人：如果《宣言》获得通过，他们中签署《宣言》的人才成为 earthling。**通过之后**，earthlings 的人数就是签署《宣言》的人数；今天从合约里读不出这个数字：关于签署的记录由我们的服务器维护，而不是名册。如何查验这个数字，将在表决之日以前公布。
- **某个具体地址在名册里有没有记录。** 以同样的方式调用 `balanceOf`。答案是 1 或 0；自二〇二六年十月二十二日起至《宣言》通过之时止，1 表示创立的参与者的临时证件，而不是护照。
- **DAO 的投票。** 打开 Snapshot 里的空间，看到提案、投票和签名。每一票都由投票人的钱包签名——我们无法伪造别人的一票。增加一名投票人可以通过在名册中发放记录来实现：合约所有者的密钥可以把记录发放到任何一个尚无记录的钱包，而每一次发放都在网络中可见。这一渠道中的票是公开的；这会带来什么改变，见“暂时还没有的东西”一节。
- **投票权。** Snapshot 向我们的服务器查询某个地址在名册中是否有记录。在投票的那一刻，这一步只能靠信任——但投票之后不必：所有投票者的地址都是公开的，任何人都可以自己在 Polygon 上的合约里逐个核对。若有不符，就会显现出来。

最后这一点我们直说，因为它是必须信任我们的地方之一。这样的地方我们宁可自己指出来，而不是留给核查的人去发现。它们有几处：投票那一刻的投票权；据以发放和销毁名册记录的合约所有者的密钥；封闭的身份验证系统关于向谁发放记录的决定；关于签署《宣言》的记录——它由我们的服务器维护，而不是名册；由平台的数据库记录的蜂巢单元投票和投票权转交；以及签名门槛为一的共同资金钱包。每一次发放、每一次销毁和每一笔资金的流动都在网络中可见，但发放的依据无法从外部核验。

其中第二处是合约所有者的密钥。在已部署的合约版本中，发放和销毁护照的功能对所有者开放，而所有者的密钥存放在发放服务的服务器上，该服务由创立者管理。《宣言》通过之后，宪章随之生效（第三十八条），它的第二十一条只允许依一种根据违背持有人的意愿销毁护照——注销无效的发放——并且必须走完程序：通知、提出异议的期限、理事会的结论、以特定多数通过的秘密投票、申诉。代码里没有这些保障——它们是程序性的；在《宣言》通过之前，既没有理事会，也没有全体大会，而创立的参与者的临时证件违背持有人意愿被销毁时，依《创立期》文件的程序（第二部分第 5 点）进行——同样是程序性的。也就是说，它们现在靠的是我们的话，而不是技术，这一点我们承认。正在做的事情是：把发放权和销毁权分给不同的角色，为销毁的执行加上延迟，并把所有权移交给选出的机构的多重签名或者移交全体大会控制。什么时候——按 [路线图](https://earth-lings.org/documents/zh/zh19-roadmap.html) 中各阶段之间过渡的条件。

## 暂时还没有的东西

下面老实列出已经宣布为原则、却还没有做到的事情：

- 合约的源代码已经发布在仓库里，但**尚未在区块链浏览器中完成验证**。这意味着，已公布的源码与已部署的字节码是否一致，需要自己去核对：从仓库构建源码，再把结果与网络中的字节码比对。
- **独立的安全审计不曾做过。** 它计划在扩大运营之前完成。
- **司库的智能合约尚未部署。** 已经部署的只有护照合约；参与的内部经济暂时记在平台的账上。
- 公开的投票渠道**已经部署，技术上也在运转，但其中还不曾有过实质性的投票**。其中的票是公开的：投票人的票和地址人人可见。《宣言》第九条要求亲自投出的一票是秘密的；秘密投票的手段还没有，正在选定，而二〇二七年二月十七日关于通过《宣言》的投票将秘密进行。转换之后，验证将不再是查看投票清单：结果将通过计票的证明和公开的重新计算软件来验证。而即便到那时，秘密也有一件事做不到：远程投票无法防范投票截止前最后一刻站在投票人背后的人；截止之前的重新投票能消除这一刻之前的强迫，却消除不了这一刻之中的强迫。
- 漏洞悬赏计划（bug bounty）已经宣布为原则，但**尚未开放**。
- **合约所有者的权限既未拆分，也未移交。** 护照的发放和销毁由同一把密钥掌握，执行上没有延迟，所有者的密钥存放在发放服务的服务器上，该服务由创立者管理。宪章第二十一条的限制是程序上的，而不是技术上的；在《宣言》通过之前，既没有理事会，也没有全体大会（宪章第三十八条），而创立的参与者的临时证件违背持有人意愿被销毁时，依《创立期》文件的程序（第二部分第 5 点）进行。
- **共同资金的钱包上还没有多重签名。** 签名门槛为一；这一点按钱包地址就能查验。把共同资金的密钥移交给选出的 Core Nodes 的多重签名或者移交全体大会控制，是路线图各阶段之间过渡的标准。

## 重建的权利

护照名册存放在区块链上，而不在我们的服务器上，合约的代码是开放的。由此得出一个很实际的结论：如果《宣言》通过之后，由于治理被夺取、基础设施停止运行或者其他情形，《宣言》的实施变为不可能，经确认的 earthlings 可以依据同一份名册，在另一种技术基础或者组织基础上把人民延续下去（《宣言》第十一条）。迁移过去的是名册的记录；服务器端的支撑部分是可以更换的。

重建有两个支点，第二个并不比第一个次要。名册给出关于已确认的人的记录的连续性（关于签署《宣言》的记录由我们的服务器维护，而不是名册），而**已公布的规格说明**给出重新组装工具的可能：规则、门槛、法定人数、期限和程序，都写在宪章、《司库》以及文集的其余文件之中。因此被重建的不是我们的代码，而是被描述出来的那套制度。复制封闭的服务器端没有必要；新的平台得自己建起自己的身份验证。

因此，服务器端的封闭并不取消人民在创立之后于没有创立者的情况下继续存在的权利。合法延续的标志——保存下来的不可修改的核心、经过验证的人的意志、程序的连续性——载于 [过渡期路线图](https://earth-lings.org/documents/zh/zh19-roadmap.html) 这份文件。
